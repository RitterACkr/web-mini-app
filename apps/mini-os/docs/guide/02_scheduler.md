# スケジューラ

## 役割

**「誰にCPUを渡すか」をきめる**

CPUがシングルコアに対してプロセスが数十個ある場合はよくある．
全員がCPUを使用したい中で，使用順を決めるのがスケジューラの役割．

## アルゴリズム比較

### 1. FCFS (First Come, First Served)

**先着順．来た順にそのまま処理する．**

```
到着順: P1 (burst=8), P2 (burst=4), P3 (burst=2)
| P1 P1 P1 P1 P1 P1 P1 P1 | P2 P2 P2 P2 | P3 P3 |
0                         8             12      14
```

- 実装は簡単
- **Convoy効果**: 重いプロセスが先頭にいると後続が待たされる
    - P1 (burst=100)が先頭にいる場合, P2, P3, ... は 100 クロック待ち続ける

---

### 2. Round Robin

**タイムスライス (量子) ごとに順番にCPUを渡す**

`タイムスライス = 2 の場合`
```
到着順 P1 (burst = 6), P2 (burst = 4), P3 (burst = 2)
| P1 P1 | P2 P2 | P3 P3 | P1 P1 | P2 P2 | P1 P1 |
0       2       4       6       8       10      12
```

- 全プロセスが定期的にCPUを使える (レスポンスタイムが良い)
- タイムスライスが小さすぎると切替コストが増える

---

### 3. Priority Scheduling

**優先度が高いプロセスを先に実行する**

```
P1 (priority = 2), P2 (priority = 5), P3 (priority = 1)
※数字が大きいほど優先度も高い

実行順: P2 → P1 → P3
```

- 重要なプロセスを優先できる
- **飢餓 (Starvation)**: 低優先度プロセスがずっと実行されない可能性
    - 対策: エイジング (Aging)
      
      待ち時間が長くなるほど優先度を少しずつ上げる
