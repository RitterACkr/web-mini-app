# I/O待ち (Waiting状態)

## I/O待ちの役割
CPUはとても速いが，ディスクやキーボードなどの `I/Oデバイス` は遅い.

```
CPU:       1命令 = 1ナノ秒
ディスク:   1読み込み = 数ミリ秒 <- CPUの100万倍遅い
```

もしこの状況でCPUがI/Oの完了を待ち続けたら,いくらCPUの性能が良くても
実際はI/Oの性能に依存した実行時間になってしまう

そこでOSは
**「I/O待ちのプロセスはCPUを手放させ,その隙に他のプロセスにCPUを渡す」**
という仕組みを持っている

これが **Waiting状態**

## 状態遷移

```
    ┌─────────────────────────────────┐
    ↓                                 │
[ Ready ] → [ Running ] → [ Waiting ]─┘
    ↓
[ Terminated ]
```
- `Running → Waiting`   : I/O要求が発生
- `Waiting → Ready`     : I/O完了

## 実際のプロセス

1. プロセスがディスク読み込みを要求
2. OSがI/Oデバイスに命令を出す
3. プロセスを `Waiting` に移行してCPUを手放す
4. OSが別のプロセスをCPUに割り当てる
5. I/O完了時にハードウェア割込みが発生
6. OSがプロセスを `Waiting → Ready` に戻す

## mini-osでの再現
実際のI/Oデバイスはないため，ボタンによって疑似的に発生させている.
時間はランダムクロック
