# メモリ管理

## メモリ管理の役割

**メモリは有限** → もし複数のプロセスがメモリを気にしなかったら
- 他のプロセスの領域を勝手に上書きしてしまう
- メモリが枯渇する

⇒ OSが「どこに・どのプロセスのデータを置くか」を管理することが大事

## mini-osのメモリモデル
便宜上，メモリ全体を **100単位** として表現．

```
メモリ全体 (100単位) :
┌───────────────────────────────────────┐
│ P1(20) │ Free(10) │ P2(30) │ Free(40) │
└───────────────────────────────────────┘
0        20         30       60         100
```

## アロケーション戦略

### First Fit

先頭から順に空きブロックを探して，**最初に見つかった十分なスペース**に配置

```
スペース: [10, 30, 20]にプロセス(size=15)を配置したい

First Fit: 2番目のスペース(30)に配置 → [10, [15+15], 20]
                                        配置↑  ↑残り
```

- 高速
- 先頭付近に小さな断片が溜まりやすい

## フラグメンテーション (断片化)

プロセスの確保・解放を繰り返すと，空き領域が細切れになる現象．

```
Before:
┌──────┬──────┬──────┬──────┬──────┐
│  P1  │ Free │  P2  │ Free │  P3  │
│ (20) │ (20) │ (20) │ (20) │ (20) │
└──────┴──────┴──────┴──────┴──────┘
空きスペースが40単位あるのに，25単位や30単位のプロセスが入らない
→ 「外部断片化」
```

### コンパクション (デフラグ)

プロセスを詰めて連続した空き領域を作る操作

```
After:
┌──────┬──────┬──────┬──────────────┐
│  P1  │  P2  │  P3  │     Free     │
│ (20) │ (20) │ (20) │     (40)     │
└──────┴──────┴──────┴──────────────┘
→ "連続した"40単位のスペースが確保できる
```
