# OS 基礎概念メモ

## プロセスとは
- プログラムの実行インスタンス
- OSはプロセスごとに **PCB (Process Control Block)** を持つ
- PCBには: PID, 状態, プログラムカウンタ, レジスタ, メモリ情報 などが入る

## プロセスの状態遷移
```
New → Ready → Running → Waiting → Terminated
                ↑__________↓ (I/O完了などで戻る)
```

- **New**: 生成中
- **Ready**: CPU待ちキューにいる
- **Running**: CPU使用中 (1コアなら同時に1つだけ)
- **Waiting**: I/O待ちなどでCPUを手放している
- **Terminated**: 終了済み

## スケジューラとは
CPUを「どのプロセスに・いつ・どれぐらい」割り当てるかを決める仕組み

### アルゴリズム一覧
| 名前 | 概要 |
|-----|-----|
| FCFS | 来た順に処理 |
| Round Robin | タイムスライスで順番に |
| Priority | 優先度順 |

## メモリ管理とは
プロセスにメモリ領域を割り当て・開放する仕組み

### アロケーション戦略
- **First Fit**: 先頭から見て最初に入る空きに配置 (速い)
- **Best Fit**: 一番ぴったりな空きに配置 (フラグメント少)
- **Worst Fit**: 一番大きい空きに配置 (大きい空きを残す)

### フラグメンテーション
- **外部断片化**: 空きは十分あるが連続していない
- **コンパクション**: プロセスを詰めて連続空きを作る操作

## PCB (Process Control Block) の詳細

JSでの実装では以下のフィールドを持つオブジェクトとして表現:

| フィールド   | 説明                        |
| ----------- | --------------------------- |
| pid         | プロセスID (一意な整数)      |
| name        | 表示名                      |
| state       | 現在の状態                   |
| priority    | 優先度 1(低) ~ 10(高)        |
| burstTotal  | CPU使用に必要な合計クロック数 |
| burstRemain | 残り実行クロック数           |
| arrivalTime | Readyキューに入った時刻      |
| startTime   | 初めてRunningになった時刻    |
| finishTime  | Terminatedになった時刻       |
| memSize     | 要求メモリ量 (全体100単位中)  |

### 状態遷移の制約

不正な遷移 (例: Terminated → Running) は VALID_TRANSITIONS テーブルで弾く設計.

### パフォーマンス指標
- **ターンアラウンドタイム** = 終了時刻 - 到着時刻
- **待ち時間** = ターンアラウンドタイム - バースト合計
